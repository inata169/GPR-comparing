# Progress record — 2026-08-11

## PyMedPhys standardization checkpoint

The source target is CPython 3.12 with PyMedPhys 0.41.0 as the standard gamma engine. The explicit Numba path remains available for legacy and research comparisons. The final local Python 3.12.10 `tests/` suite completed with `134 passed, 7 skipped, 13 warnings`; Ruff and the report-schema example completed without findings.

The controlled full-volume 5 x 5 cm source-GUI and Fast 3D Viewer checks are recorded separately in [PyMedPhys controlled RTDOSE verification record — 2026-08-11](PYMEDPHYS_CONTROLLED_RTDOSE_VERIFICATION_2026-08-11.md).

The project owner also froze the current release-preparation policy: keep PyMedPhys exactly at 0.41.0 until a separately reviewed validation cycle; reject `norm=none` fail-closed for PyMedPhys; do not make numerical equality with the legacy/experimental Numba engine a release criterion; defer peak-memory characterization without making a performance claim; and retain clean-machine installation testing as an explicit pending item.

## Limitations and pending acceptance

- The ZIP was built from a worktree explicitly marked `dirty-validation-only`; it is a validation candidate, not an approved release artifact.
- `--no-index` installation verification demonstrates that the wheelhouse is self-contained for the exercised environment, but the PC itself was not physically disconnected from the network.
- No Windows x64 PC without Python is currently available. Clean-machine first-install acceptance remains pending by project-owner decision.
- The candidate offline ZIP is not attached to v0.9.3 and receives no clean-machine or offline-installation approval from the source release. No clinical-use approval is implied.
- Source/derived DICOM and generated case results remain local and are not included in the bundle or repository.
