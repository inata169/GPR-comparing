## Fixed-condition source-workflow verification

The corrected evaluation RTDOSE was used with Frame of Reference mismatch permission disabled. The two controlled conditions were kept separate:

| Purpose | Engine | Interpolation fraction | Elapsed time | GPR | Evaluated points |
| --- | --- | ---: | ---: | ---: | ---: |

JSON, CSV, Markdown, PDF, charts, SQLite, `gamma3d.npz`, and `diff3d.npz` were generated. The cache contract and report schema were validated. Ref Dose, Eval Dose, Dose Diff, Dose Ratio, Gamma, and Pass/Fail rendered from the validated cache. Dose-only fallback and abnormal Viewer-exit reporting were also checked.

This is software functional evidence only. It is not clinical QA, patient-dose approval, commissioning, a medical-device claim, or a clinical GPR threshold.

## TPS-PC operational result and final publication decision

On 2026-08-27, the project owner reported that the prescribed v0.9.6 EXE operational check on the TPS PC completed successfully. This closes the approved distribution-specific check without converting it into a second fixed-condition acceptance study. No additional GPR, elapsed-time, screenshot, log, or generated-output value was supplied for this closeout, so none is inferred or added to the fixed-condition source results above.

The project owner initially approved publishing the two locally verified archives. After the source-only Release page had been created with no assets, a subsequent license-material audit performed before any binary-asset upload found that the Fast EXE ZIP includes the PyInstaller `COPYING.txt` and a Qt/PySide6 notice, but does not include the GPR-comparing MIT `LICENSE` text or the official LGPL/GPL texts applicable to the bundled Qt/PySide6 Community Edition components. The offline ZIP does include the project `LICENSE` and the pinned official Qt license texts. This finding does not make the MIT-licensed application incompatible with PyInstaller: PyInstaller's bootloader exception permits distributing generated bundles under another license. The finding instead concerns incomplete license-material collection in the Fast EXE packaging path.

The project owner then confirmed the final decision to keep [GitHub Release `v0.9.6`](https://github.com/inata169/GPR-comparing/releases/tag/v0.9.6) source-only with zero uploaded assets and corrected the Release notes accordingly. They explicitly state that neither a compiled EXE nor an offline installation ZIP is published. The existing annotated `v0.9.6` tag remains unchanged at `cbc1b6cadf145b27ce659a020192e0c550bf264d`.

Do not publish or externally hand off the current Fast EXE ZIP as a standalone distribution. Copying it only between systems controlled by the same organization may be an internal-use case, but transfer to another individual or organization can be distribution and must not be assumed exempt from license obligations. Before any external binary distribution, update the packaging workflow to include the project MIT license and the pinned official Qt/PySide6 license texts, fail closed when required material is missing, and repeat package verification. Prefer a newly approved version and exact source tag, expected to be `v0.9.7`; do not move the published `v0.9.6` tag.
