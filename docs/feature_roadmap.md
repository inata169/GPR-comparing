## Tier 1: コア品質と信頼性（最優先）

商用ソフトとしての「品質の土台」。ここが弱いと他の機能が信用されない。

### 1.1 バッチ処理 & 自動化パイプライン
- **課題**: 現在は1ペアずつ手動実行。臨床では患者数十件を一括処理したい。
- **提案**:
  - `--batch` モード: CSVやフォルダ構造で複数ペアを定義し一括実行
  - 患者ごとのサマリテーブル自動生成（全患者×全ROI の GPR マトリクス）
  - エラー耐性: 1件の失敗で全体が止まらないスキップ＋ログ

### 1.2 PDF レポート自動生成
- **課題**: Markdown レポートは開発者向け。臨床QAには「そのまま印刷・承認できる」帳票が必要。
- **提案**:
  - ヘッダ（施設名・日付・装置名・物理士名）＋ガンママップ画像＋ROI GPR テーブル＋署名欄
  - テンプレートベース（`reportlab` or `weasyprint`）
  - 施設ロゴ・カスタムヘッダ対応

### 1.3 テスト自動化・CI 強化
- **課題**: テスト 9件。合成データ中心で、結合テスト・回帰テストが不足。
- **提案**:
  - カバレッジ計測（`pytest-cov`）と目標値の設定（≥80%）
  - End-to-end テスト: CLI→レポート出力→JSON スキーマ検証を一気通貫
  - ゴールデンファイルテスト: 既知データの GPR が変わっていないことを回帰検証
  - GitHub Actions CI でテスト + lint (`ruff`) を自動実行

### 1.4 RTPLAN 統合ヘッダ比較
- **課題**: TODO に記載済み。Isocenter/SAD/SSD の差が GPR 低下の原因特定に必須。
- **提案**:
  - [compare_rtdose_headers.py](file:///c:/Repositories/GPR-comparing/scripts/compare_rtdose_headers.py) に `--plan-a`/`--plan-b` 追加
  - Isocenter 座標差・SAD/SSD 差のレポート出力
  - ビューアに Isocenter マーカーの重畳表示

## Tier 2: ユーザー体験の飛躍（差別化機能）

「使いやすい」から「一度使ったら手放せない」へ。

### 2.1 Web GUI（クロスプラットフォーム）
- **課題**: 現在の GUI は PowerShell/WinForms のため Windows 専用。
- **提案**:
  - Flask/FastAPI + React（or Streamlit）による Web アプリケーション
  - ファイルアップロード → 解析 → 結果表示 → PDF ダウンロードの一貫フロー
  - 複数ユーザー・セッション管理、進捗のリアルタイム表示（WebSocket）
  - Docker コンテナ配布で「`docker run` 一発で起動」

### 2.2 3D ビューアの高度化
- **課題**: Matplotlib は高速描画に限界がある。スクロール時のカクつきや断面切替の遅延。
- **提案**:
  - **DVH（Dose-Volume Histogram）表示**: 各ROIのDVHカーブを別パネルに表示
  - **マルチプレーン同時表示**: Axial/Sagittal/Coronal の3画面レイアウト（同一スライス位置をクロスヘアで連動）
  - **プロファイルライン**: 任意の直線上の線量プロファイル（Ref vs Eval）を表示
  - **アノテーション**: スナップショット保存時に矢印・テキスト注釈を追加
  - **（将来）VTK/PyVista ベースの3Dボリュームレンダリング**

### 2.3 解析結果のデータベース化
- **課題**: 結果が個別ファイルに散在。過去の解析との比較やトレンド分析が困難。
- **提案**:
  - SQLite ベースのローカル DB に解析結果を自動保存
  - 患者ID・プラン名・日時・GPR・各統計値をインデックス
  - 時系列トレンド表示: 「この装置のモンテカルロ vs CCC の GPR は月次でどう推移しているか」
  - 検索・フィルタ・CSV エクスポート

### 2.4 設定プリセット管理
- **課題**: DTA/DD/Cutoff を毎回手入力。施設のプロトコル（AAPM TG-218 基準など）を保存・共有したい。
- **提案**:
  - YAML/JSON プリセットファイルの保存・読み込み
  - 名前付きプリセット: `TG218_IMRT`（3%/2mm/10%）、`TG218_VMAT`（3%/2mm/10%）、`SRS_strict`（1%/1mm/5%）
  - プリセットのインポート/エクスポート（施設間共有）

## Tier 3: 高度解析機能（旧アイデア）

以下は過去に検討された機能案であり、商用システムとの同等性または優越性を示すものではありません。

### 3.1 ガンマヒストグラム & 統計ダッシュボード
- **提案**:
  - ガンマ値のヒストグラム表示（全体 / ROI 別）
  - 分位点（P50, P90, P95, P99）と分布の非対称性の定量化
  - 「どこが、なぜ失敗しているか」を直感的に把握するための空間分析マップ

### 3.2 多基準同時評価（Multi-Criteria）
- **提案**:
  - 1回の解析で複数の基準（3%/3mm, 3%/2mm, 2%/2mm, 1%/1mm）を並行計算
  - 各基準の GPR をテーブル・レーダーチャートで一覧表示
  - "Acceptance Window": どの基準まで合格するかを自動判定

### 3.3 トレランスレベル & アラート
- **提案**:
  - GPR の閾値設定: Action Level（例: < 90%）、Tolerance Level（例: 90-95%）
  - 閾値違反時にレポートに自動で WARNING/FAIL ラベルを付与
  - バッチ処理と組み合わせて「異常値だけをハイライトしたサマリ」を自動生成

### 3.4 不確かさ推定（Uncertainty Estimation）
- **提案**:
  - 線量グリッド解像度・ノイズがガンマ結果に与える影響のブートストラップ推定
  - シフト最適化結果の信頼区間表示
  - 「GPR = 95.2% ± 0.8%」のような不確かさ付き報告

### 3.5 対応フォーマットの拡張
- **提案**:
  - **MHD/NRRD/NIfTI** 線量分布の読み込み（PHITS, Geant4, TOPAS 等のMCシミュレーション出力）
  - **水ファントム測定データ**（W2CAD, OmniPro）の読み込みと比較
  - RTDOSE 以外の線量出力（Eclipse AAA vs AcurosXB のDICOM出力比較など）

## まとめ — 「売り物並み」に必要な最低ライン

商用品質への最短パスは以下の **5つのコア改善**:

1. **バッチ処理** — 「1件ずつ」から「全患者一括」へ
2. **PDF レポート** — 「開発者のログ」から「QA帳票」へ  
3. **テスト & CI** — 「動いている気がする」から「証明されている」へ
4. **RTPLAN 統合** — 「なぜ合わない？」を即座に突き止められるように
5. **設定プリセット & トレランス** — 施設のプロトコルを正確に反映

これらを実装すれば、SNC Patient や MapCHECK 等の商用ソフトウェアと同等の"信頼度"と"使い勝手"の基盤が整います。
